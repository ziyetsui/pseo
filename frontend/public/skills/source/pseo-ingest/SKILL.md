# 收集并整理第一批数据

你需要把 API、CSV 或网页资料变成能检查、能重跑的数据。

## 输入与范围

来源合同；现有原始文件或已授权的采集入口与预算。

可单独使用，不要求已运行整套流程。读取用户指定的产物与适用项目规则；缺必需输入时先复用已有材料，只补问阻塞当前步骤的信息。默认将新产物保存到 `docs/pseo/`，用户指定位置优先。不要因使用本 skill 扩大任务、生产权限或费用范围。

## 执行

1. 先用一条样本验证输入解析与字段映射，再执行已约定范围。原始数据先保留安全副本/引用，规范化记录附 raw_ref，不输出认证信息或私有正文到日志。

2. 稳定来源 ID 保持字符串；去重保留来源关系；指标缺失用 null 加 missing_reason。不要把规范化、提取、推断和人工判断混成同一字段。

3. 请求账本记录 query/source、页数、游标、停止原因和错误。自然结束与达到上限、重复游标、限流、权限失败分开；受限运行标 partial，不称全量。

4. 产出 raw/（安全且可保存时）、normalized.jsonl、ingest-manifest.json、05-data-report.md。manifest 至少有 schema_version、来源范围、记录数、失败数、时间和停止原因，不保存凭据。

5. 用重复 id、缺字段、损坏记录、来源冲突检查质量；抽样回查源。断点恢复不重复产物，不在失败时改用未授权数据源。

6. 普通 CSV 也走字段校验与去重，不为了套流程引入网络采集或付费工具。

## 交付与完成条件

主交付：`05-data-report.md`（规范化数据与质量报告）。记录输入版本、证据位置、实际检查、未知与阻塞。

- 每条规范化记录能回溯原始来源；失败被报告而非吞掉。
- 数量与实际文件一致，partial 范围写清，预算未扩大。

若项目已有 `project.json` 进度记录，只有完成条件有证据时才更新本步骤为 complete；缺口写 blocked，未实测写 not_checked，不把个人学习勾选当工程证据。上游 revision 变化后重查受影响结论。

下一步通常是 `pseo-graph`，但以用户当前目标和真实缺口为准。未安装下一项时说明缺项；本步骤仍可独立交付，不假装调用成功。
