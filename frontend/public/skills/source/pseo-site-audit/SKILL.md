# 了解你的网站

你已经有网站，想知道从哪里开始做 PSEO。

## 输入与范围

网站 URL 或仓库；用户已提供的业务目标和访问范围。

可单独使用，不要求已运行整套流程。读取用户指定的产物与适用项目规则；缺必需输入时先复用已有材料，只补问阻塞当前步骤的信息。默认将新产物保存到 `docs/pseo/`，用户指定位置优先。不要因使用本 skill 扩大任务、生产权限或费用范围。

## 执行

1. 优先读取网站首页、一个产品页、一个现有内容页、站点地图或仓库路由与内容模型。记录实际访问的范围、时间与失败；URL 不可访问时继续分析已有文件，不编造网站事实。

2. 提取产品为谁解决什么任务、现有转化动作、主要 locale、可重复的数据对象、当前内容来源和更新责任人。技术栈有代码证据才确定；仅从网页观察则注明推断。

3. 按 维度｜现状｜证据位置｜影响｜下一步 输出基线。区分新建页面族、改造已有目录、修复已上线页面，不默认重建整个站。

4. 只补问不能从现有材料推导且会改变方向的信息，例如业务结果或可用数据。没有搜索平台权限仍可完成有范围声明的基线；不把无权限当作没有流量。

## 交付与完成条件

主交付：`01-site-audit.md`（网站基线与缺口清单）。记录输入版本、证据位置、实际检查、未知与阻塞。

- 读者能看到审计覆盖了哪些 URL/文件，以及哪些仍未知。
- 找到一个真实的用户任务和转化入口，或明确把这两项列为阻塞；没有把推测写成现状。

若项目已有 `project.json` 进度记录，只有完成条件有证据时才更新本步骤为 complete；缺口写 blocked，未实测写 not_checked，不把个人学习勾选当工程证据。上游 revision 变化后重查受影响结论。

下一步通常是 `pseo-opportunity`，但以用户当前目标和真实缺口为准。未安装下一项时说明缺项；本步骤仍可独立交付，不假装调用成功。
