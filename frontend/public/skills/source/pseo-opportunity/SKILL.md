# 选一个值得做的方向

你有几个方向，想先选出最值得验证的页面族。

## 输入与范围

网站基线、业务目标、已有产品与数据资源。

可单独使用，不要求已运行整套流程。读取用户指定的产物与适用项目规则；缺必需输入时先复用已有材料，只补问阻塞当前步骤的信息。默认将新产物保存到 `docs/pseo/`，用户指定位置优先。不要因使用本 skill 扩大任务、生产权限或费用范围。

## 执行

1. 从用户任务提出少量可比较的页面族候选，例如用途、兼容关系、对比、目录或可执行工具。每个候选写清用户得到什么独特帮助，不能只列关键词。

2. 用 候选｜用户任务｜需求证据｜独有数据/能力｜转化动作｜维护成本｜阻塞 比较。未知搜索量保持未知；社交互动只证明注意力，不能当搜索需求。

3. 有已授权的 Search Console 导出、关键词数据或客服问题时引用它们；否则做有限公开 SERP 观察并标记定性证据。工具不可用时接受 CSV/人工研究，不强制订阅服务。

4. 选择一个可用真实样本验证的方向，说明其他方向为什么后置。没有数据优势或任务差异时建议先补数据或改现有页面，不硬凑 PSEO。

5. 给出试点范围、成功观察点、停止条件。不要承诺排名、收入或固定收录周期。

## 交付与完成条件

主交付：`02-opportunity.md`（首个页面族的决策）。记录输入版本、证据位置、实际检查、未知与阻塞。

- 选择理由可追溯到真实证据，假设单独标记。
- 至少能说明页面解决的任务、独特信息、可持续来源和下一步试验；不能满足时给出明确补证据动作。

若项目已有 `project.json` 进度记录，只有完成条件有证据时才更新本步骤为 complete；缺口写 blocked，未实测写 not_checked，不把个人学习勾选当工程证据。上游 revision 变化后重查受影响结论。

下一步通常是 `pseo-intents`，但以用户当前目标和真实缺口为准。未安装下一项时说明缺项；本步骤仍可独立交付，不假装调用成功。
