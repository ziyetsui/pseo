# 建立对象与关系

你有一批资料，需要把它们整理成页面能复用的数据结构。

## 输入与范围

规范化样本、意图表和领域术语。

可单独使用，不要求已运行整套流程。读取用户指定的产物与适用项目规则；缺必需输入时先复用已有材料，只补问阻塞当前步骤的信息。默认将新产物保存到 `docs/pseo/`，用户指定位置优先。不要因使用本 skill 扩大任务、生产权限或费用范围。

## 执行

1. 区分稳定实体、属性、关系、来源证据与用户任务。原始帖子/网页通常是证据，不自动成为产品详情对象。

2. 定义实体 id/type/attributes/source_refs，关系 from_id/type/to_id/evidence_refs，以及 locale 展示层。没有证据的关系标 proposed，不进入公开导航。

3. 给出实体注册表、别名归并、边允许类型与基数、悬空引用和循环处理。优先普通 JSON/关系表，只有实际查询需要才选图数据库。

4. 拿真实样本走通至少一个对象与两种有意义的视图，如用途发现与对象详情；缺关系时保留缺口，不制造边凑例子。

5. 输出 graph.json 和 06-graph.md，说明 identity 与可变 slug 分离、来源更新影响哪些对象；不在此阶段把每条边发布成 URL。

6. 为每个将成为页面的节点导出**邻域视图**（`neighborhood.json`）：up（父节点）、across（同轴兄弟）、down（子节点/所列对象）、related（其他有证据的边），每组带目标 id、计数与 status。只收 accepted 且端点存在的边；这是页面 IA 页脚的唯一来源，页面不得自行编造相邻链接。

## 交付与完成条件

主交付：`06-graph.md`（实体、属性与关系合同）。记录输入版本、证据位置、实际检查、未知与阻塞。

- 实体不是关键词 token 清单；每条接受的边有证据且端点存在。
- 同一对象可在不同视图复用，不复制出不一致的事实。
- 每个页面节点都有邻域视图；up 与 down 为空的节点要说明原因（孤立节点通常不该成为页面）。

若项目已有 `project.json` 进度记录，只有完成条件有证据时才更新本步骤为 complete；缺口写 blocked，未实测写 not_checked，不把个人学习勾选当工程证据。上游 revision 变化后重查受影响结论。

下一步通常是 `pseo-page-plan`，但以用户当前目标和真实缺口为准。未安装下一项时说明缺项；本步骤仍可独立交付，不假装调用成功。
