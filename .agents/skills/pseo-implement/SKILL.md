# 跑通第一个页面族

你有明确规格，准备把数据和模板接到真实代码里。

## 输入与范围

清晰的接入架构、模板规格、工程授权、数据样本与本地环境。

可单独使用，不要求已运行整套流程。读取用户指定的产物与适用项目规则；缺必需输入时先复用已有材料，只补问阻塞当前步骤的信息。默认将新产物保存到 `docs/pseo/`，用户指定位置优先。不要因使用本 skill 扩大任务、生产权限或费用范围。

## 执行

1. 检查 git status、根与目标目录规则、相关规格；保留并发修改。只修改约定工程范围，不编辑受治理的生成内容。

2. 先完成一条数据→校验→路由→首屏/正文→真实行动的纵向链路，再复用模板到该页面族。外部数据按 unknown 校验和映射；不把 API 缺口吞成空库。

3. 正文与有效链接必须存在于宿主支持的可抓取 HTML 中。客户端交互限制在必要边界，避免为筛选/按钮把整页变成 JS 空壳。

4. 实现真实空态、错误、未知对象与缺译文行为，保持 ID/slug/locale 一致。用合法样本与失败样本验证，不为过测试伪造已审核内容。

5. 执行宿主要求的 lint/typecheck/tests/build 及核心浏览路径；记录实际命令、退出状态、环境限制与产物。只在新变化或失败有理由时扩大测试。

6. 交付工程 diff 与 11-implementation.md，区分本地可运行和生产上线。不顺带部署、改 DNS 或推受保护主分支。

## 交付与完成条件

主交付：`11-implementation.md`（可运行代码与检查记录）。记录输入版本、证据位置、实际检查、未知与阻塞。

- 首个页面族真实可运行，数据/路由与主要行动经检查。
- 规定工程门禁有真实结果，失败和未运行不会被写成通过。

若项目已有 `project.json` 进度记录，只有完成条件有证据时才更新本步骤为 complete；缺口写 blocked，未实测写 not_checked，不把个人学习勾选当工程证据。上游 revision 变化后重查受影响结论。

下一步通常是 `pseo-technical-seo`，但以用户当前目标和真实缺口为准。未安装下一项时说明缺项；本步骤仍可独立交付，不假装调用成功。
