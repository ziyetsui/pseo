# Spec

Translate evidence and user intent into a build contract stored in `specs/`.

## Workflow

1. Read the relevant research in `docs/`, existing specs, and current project structure.
2. Define the problem, user outcome, goals, and non-goals.
3. Specify observable behavior, constraints, interfaces, and important data flow.
4. Write testable acceptance criteria and identify risks or unresolved decisions.
5. Order implementation work by dependency and user-visible milestones.

Right-size the document to the decision. Do not invent requirements, hide uncertainty, or add sections that answer no real question. If evidence is missing, return to `research` before finalizing the contract.
