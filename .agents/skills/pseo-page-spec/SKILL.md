# 定义一张真正有用的页面

你知道要做哪些页面，需要明确每种页面必须展示什么。

## 输入与范围

已选页面族、页面计划、真实数据样本与转化目标。

可单独使用，不要求已运行整套流程。读取用户指定的产物与适用项目规则；缺必需输入时先复用已有材料，只补问阻塞当前步骤的信息。默认将新产物保存到 `docs/pseo/`，用户指定位置优先。不要因使用本 skill 扩大任务、生产权限或费用范围。

## 执行

1. 先写用户落地后要完成的任务和完成信号，再倒推最低必需信息。不要先套标题/FAQ/固定字数模板。

2. 定义 字段｜类型｜必需条件｜来源｜缺失处理｜展示位置。产品对比需要可验证差异，目录需要可判断和筛选的属性，教程需要真实步骤，Prompt 才需要可执行指令与输入。

3. 区分必需字段和增益字段。缺核心数据时阻塞页面候选或给真实空态；不写虚假作者、评价、效果、价格或更新日期。

4. 定义主行动、来源/更新时间展示，以及 loading/empty/error/404/缺译文状态。JSON-LD 类型只能对应页面可见事实。

4b. **IA 页脚是必需模块**，与宿主站点页脚分开：渲染本页在图谱中的节点与边——up（父页，≥1 条必需）、across（同轴兄弟，可为空但要说明）、down（子页/所列对象，≥1 条必需）、related（其他有证据的边）。字段表里加 `ia_footer` 一行，来源只能是 `pseo-graph` 的邻域视图；每组限量并带数量文案；目标不存在或边无证据则不渲染该条；服务端渲染。up 或 down 为空 → 页面阻塞。

5. 用一条真实记录走读所有模块，写出可验证验收；设计一个缺核心字段的负例，保证不被误当作完整页面。

6. 输出模板合同与 sample mapping，标明哪些文案是原创说明、哪些来自数据；未经批准不改写作者原文。

## 交付与完成条件

主交付：`08-page-spec.md`（页面模板与字段合同）。记录输入版本、证据位置、实际检查、未知与阻塞。

- 必需模块均由用户任务解释，真实记录能够填充或明确阻塞。
- 一个明确的失败样本会被正确拒绝，不用占位事实通过验收。
- IA 页脚四个方向的目标都能回溯到邻域视图，且真实记录能填出 up 与 down。

若项目已有 `project.json` 进度记录，只有完成条件有证据时才更新本步骤为 complete；缺口写 blocked，未实测写 not_checked，不把个人学习勾选当工程证据。上游 revision 变化后重查受影响结论。

下一步通常是 `pseo-prototype`，但以用户当前目标和真实缺口为准。未安装下一项时说明缺项；本步骤仍可独立交付，不假装调用成功。
