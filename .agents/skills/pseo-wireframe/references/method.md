# 从真实项目提炼的方法

这是对项目发展步骤的通用化，不是对历史对话或课程的逐字转录。来源文件名仅用于解释推导；独立 skill 运行无需原仓库。

| 项目中发生的步骤 | 可复用规则 | 放到当前七步 |
| --- | --- | --- |
| 先归档参考和同事项目，再追问第一性原理（0001） | 先把材料与问题放在同一个范围，形成可验证目标 | 1 |
| 从 Information → Entity / Attribute / Relation → Intent / View → Surface（0002、0003） | 用户任务决定视图，页面是数据投影；实体不等于关键词 | 2、4 |
| 从特定来源发现对象并保留来源证据（两个 0004） | 来源平台是可替换适配器；页面对象与来源帖子分开 | 3 |
| 为“复现结果”推导最小完整字段（0005） | 先解释用户需要什么再定模块；对象、输入、结果、证据、行动分别建模 | 5、6 |
| 把采集写成规格与可观察验收（0006、0007） | 先小样本，唯一 ID、可追溯、明确缺失和 partial，不能把部分完成写成全量 | 3、7 |
| 从详情扩展到 L1–L4 路由与核心旅程（0008） | 一份真实样本贯穿四层，路径与失败状态进入验收 | 5、6、7 |
| 把 UI、领域数据、API、发布边界分开（0009） | 先可评审原型，后接入宿主工程；不绑定单一框架 | 后续实施 |
| 废弃旧 Git 内容发布链，改 CMS 审核与不可变快照（0011） | 历史步骤会过期，按当前合同执行；生成、批准、发布分开 | 7 / 后续 |
| 十九个 skills 与六阶段方法包（0012） | 大流程渐进加载，给新手一个短闭环，熟练者可从任一步进入 | 总入口 |
| 训练营沉淀的“场景 → 实例 → 规则 → 草稿；脚本先跑通再封装” | Agent 负责判断，脚本负责稳定渲染，实测后再交付 | 全程 |

## 用户可以使用的完整路线

1. **发现**：现场与资料审计 → 机会假设 → 用户任务。
2. **数据**：来源合同 → 小样本规范化 → 对象与关系。
3. **页面**：页面资格与信息架构 → 模板字段 → 四层 wireframe → 走查。
4. **工程**：宿主架构 → 首个页面族实现 → 技术 SEO。
5. **发布**：草稿与人工审核 → 质量门禁 → 授权发布及线上回执。
6. **迭代**：真实数据测量 → 更新 / 合并 / 撤下 → 有依据地扩展。

本 skill 实际执行前三段的入门闭环。数据不足时产出假设结构，不冒充完成市场研究；采集与生产实施继续使用宿主工具。

## 刻意不固化的项目细节

不固定产品品牌、来源平台、API、私有路径、某次采集数量/热度阈值、技术栈或视觉风格。原型使用中文低保真模板是首版实现选择，不是 PSEO 的普遍要求。

## 反证与停止条件

如果多个页面回答同一问题，合并候选；如果字段无法支撑用户决定，补数据或缩小范围；如果来源/权利不清晰，保留待审状态；如果原型主路径走不通，先修正再进入工程。不得通过填充虚构事实绕过缺口。
