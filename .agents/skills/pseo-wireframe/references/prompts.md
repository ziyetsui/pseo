# 可以直接使用的 Prompt

## 从新想法开始

使用 pseo-wireframe。我准备做【网站类型】，面向【读者】，帮助他们【任务】。已有材料是【路径或描述】。先读材料复用已有答案，每次只问影响当前步骤的关键选项。按目标、任务、样本来源、对象关系、页面计划、模板原型、走查七步推进，最终交付可浏览的首页、分类、集合、详情与 project.json。没有数据时把示例清楚标出来。

## 把现有项目变成原型

使用 pseo-wireframe，查看【项目路径】中适用规则、规格、数据和现有页面。把已确认目标与资料提取到输入合同。保留对象、来源和结果证据的区别，用一份样本贯穿页面。生成到新的输出目录，并实际核对导航、搜索、主要行动和窄屏效果；不要修改生产系统。

## 继续修改

读取【输出目录】的 project.json、progress.json 和 06-review.md。新输入：【改变的目标/样本/分组/行动】。说明变更影响的步骤，复用其他已确认信息，生成新版本并重新验证受影响路径。给我新的原型、输入文件、缺口和变化摘要。

## 交给下一个 Agent

先读产物再行动。planner 负责将输入映射为目标、任务与页面合同；builder 调用固定生成器；reviewer 按真实浏览器证据更新走查记录。三个职责可以由同一助手顺序完成。所有结论区分 supplied、hypothesis、derived、verified；未运行检查不得写成通过。达到原型终点后，再按用户范围进入工程和发布流程。
