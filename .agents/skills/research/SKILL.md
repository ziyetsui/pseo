# Research

Answer a concrete question with evidence before proposing a build direction.

## Workflow

1. State the decision or uncertainty being researched.
2. Inspect relevant project files and existing material in `docs/` and `specs/`.
3. Gather only the evidence needed to reduce that uncertainty.
4. Separate verified facts, reasonable inferences, and open assumptions.
5. End with a decision, recommendation, or explicit next action.

When a durable artifact is useful, write it under `docs/` with a clear descriptive name. Include sources or reproducible evidence, key findings, implications for the project, and unresolved questions.

Do not write implementation code or lock a specification while load-bearing evidence is still missing.
