# 用真实样本试一遍

你想在开发前看见页面，并验证它是否真的帮用户完成任务。

## 输入与范围

页面合同、可用真实样本、宿主网站视觉规范。

可单独使用，不要求已运行整套流程。读取用户指定的产物与适用项目规则；缺必需输入时先复用已有材料，只补问阻塞当前步骤的信息。默认将新产物保存到 `docs/pseo/`，用户指定位置优先。不要因使用本 skill 扩大任务、生产权限或费用范围。

## 执行

1. 读取宿主设计合同与现有页面，保留其品牌、字体和导航习惯。用户没有要求多方案时先做一个明确方向；需要比较时用少量有实质区别的方案。

2. 以真实样本渲染首屏、主体、来源、主行动、相关页。素材无使用依据则采用真实缺失状态，不用随机图伪装成果。

3. 打通入口到详情和下一步；尚未实现的外部动作说明不可用，不放成功假按钮。原型与生产内容隔离并 noindex；敏感草稿需要真实访问保护，noindex 不是权限。

4. 检查窄屏、长文本、空数据、媒体失败与键盘导航；核心内容即便无 JS 也可读。记录体验问题而不只交截图。

5. 交付可打开的原型、数据来源范围与 09-prototype-review.md。注明哪些属于原型模拟、哪些操作真实生效。

## 交付与完成条件

主交付：`09-prototype-review.md`（可交互原型与走查记录）。记录输入版本、证据位置、实际检查、未知与阻塞。

- 用户能用一条样本完成核心浏览与判断路径。
- 交互与失败状态已实际检查，原型不被称作可索引生产页面。

若项目已有 `project.json` 进度记录，只有完成条件有证据时才更新本步骤为 complete；缺口写 blocked，未实测写 not_checked，不把个人学习勾选当工程证据。上游 revision 变化后重查受影响结论。

下一步通常是 `pseo-prototype-polish`（原型能用但视觉未定时），否则 `pseo-architecture`；以用户当前目标和真实缺口为准。未安装下一项时说明缺项；本步骤仍可独立交付，不假装调用成功。

## 示例请求

> 按现有网站风格做一个真实样本的页面原型，验证从发现到转化的路径。
