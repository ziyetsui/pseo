## 0. 产品定义

这是一个面向 AI Prompt 的 PSEO 内容站，也是一个 CMS-first、Git-public-mirror 的内容系统。

它不以“自动批量写 SEO 文章”为核心，而是：

- 从 X、RSS、URL 等来源发现有用内容；
- 将原始 payload 规范化为有证据的 Prompt Artifact；
- 用固定但可扩展的页面模板呈现；
- 在 Payload 中保存 canonical 内容与审核 revision，再确定性生成每内容、每语言独立 Markdown；
- 同时支持 Agent draft proposal 与 CMS 表单编辑，但人工批准和权利决策统一落在 CMS；
- 已批准 CMS snapshot 通过校验后，由专用 mirror bot 生成 Markdown/索引/多语言 README 并直推公开镜像 `main`；
- 生产以精确 mirror commit 与 manifest 部署，部署与 smoke 成功后才标记 released；
- 同时提供列表、详情、分类、RSS、Sitemap、SEO 和多语言基础设施。

一句话：

> 用户来这里是为了找到、理解、复制并成功使用 Prompt；运营者和 Agent 在 Payload 工作，人决定什么可以发布，Git 公开镜像记录 CMS 已批准快照，部署证据决定什么已经 released。

### 0.1 当前规范

当前发布路径为 `Issue/Editor/Agent proposal → CMS draft → human approval + rights review → immutable export snapshot → deterministic validation/build → mirror bot direct push main → production deploy/smoke → released receipt`。GitHub 内容 PR 不再是当前内容发布门禁；代码和自动化 PR 不受此变化影响。

## 1. 背景与问题

### 1.1 用户问题

现有 Prompt 来源分散在 X 等平台：

- 搜索困难；
- 原帖容易失效；
- Prompt 与效果、输入、变量、步骤脱节；
- 很难按模型、用途、技法、风格发现；
- 复制后仍不知道怎么复现结果；
- 多语言内容缺少清晰版本关系。

### 1.2 运营问题

未版本化、没有 revision-bound 审核与导出证据的传统 CMS 容易形成不可审计的单点真相：

- 内容改动缺少代码式 review；
- Payload 草稿、Git 文件和线上页面可能出现三份不同版本；
- 自动翻译可能悄悄覆盖人工译文；
- 大规模 PSEO 容易生成薄内容、重复页和虚假数量；
- 抓取数据、已审核内容和公开页面边界不清。

### 1.3 当前原型审查

flow-proto 已表达四层信息架构和主要交互，但不是生产代码：

- 四页被嵌在 srcdoc iframe 中，使用 hash 路由；
- 原型外壳缺少显式 charset；本地 HTTP 截图已出现中文 mojibake；
- 没有独立可索引 URL；
- 宣称 982/324/136 条，但原型只嵌入样本卡；
- L1、L2、L3 的筛选组合语义不一致；
- 部分复制失败仍显示成功；
- 图片依赖 X 热链；
- 缺 loading、error、retry、404、媒体失败和缺翻译状态；
- 缺 Blog、RSS、canonical、hreflang 和结构化数据；
- 视觉原型是中性深色 UI，而 UI Spec 是 Bauhaus 浅色体系。

本 PRD 保留 wireframe 的信息架构和任务流，不保留 iframe/hash/硬编码实现。

## 2. 用户与 Jobs to Be Done

### 2.1 Prompt 使用者

当我想用某个模型完成具体视觉任务时，我希望：

1. 快速按模型、用途、技法或风格找到可用 Prompt；
2. 在复制前看到效果、所需输入、变量和步骤；
3. 确认来源和证据；
4. 替换变量后一次复制；
5. 继续浏览真实相关的 Prompt。

### 2.2 搜索访问者

当我从 Google 进入具体页面时，我希望：

- 页面直接回答查询，而不是把我送到空列表；
- 正文在首次 HTML 中可读；
- 标题、来源、更新时间和适用模型明确；
- 语言正确，不混入 fallback 正文。

### 2.3 内容审核者

当系统从 X 等来源发现候选时，我希望：

- 看见原始内容、规范化结果和证据；
- 修正分类和页面字段；
- 保存草稿；
- 完成 rights path 与 revision-bound 人工批准；
- 在受保护的 CMS Preview 中检查；
- 镜像同步和部署后能追踪到 CMS revision、Git mirror commit 与生产页面。

### 2.4 内容工程 Agent

主要面向开发者、创始人和 SEO 内容工程师。当我通过 Codex/Claude Code，或受控的 Codex SDK runner，提出“加一篇博客”“改标题”“挂到 `/blog`”或“修改某个 Prompt”的自然语言请求时，我希望：

- 将用户提供的正文、outline 或明确 brief 按 schema 转为 CMS draft proposal；
- 自动处理 immutable id、locale、slug、路由关系和安全默认值；
- 运行确定性校验；
- 只提议目标内容和必要关系，不直接编辑生成镜像；
- 创建清晰 proposal diff、Preview 和审核摘要；
- 不绕过 review，不读取 secret，不伪造事实、来源、翻译或可索引资格。

Agent 不是新的权限角色；它只能使用发起者已有权限。Internal Beta 可直接以 Codex/Claude Code 作为操作界面，也可由 server-side Codex SDK runner 执行同一 Skill；不要求用户进入 Payload，也不在 Payload 内嵌聊天 UI。

## 5. 核心用户旅程

### Journey A｜从首页找到并复制 Prompt

1. 用户进入 zh-CN/prompts；
2. 搜索或选择 model/use_case/technique/style；
3. URL query 同步更新；
4. 列表 count、facets 与结果一起更新；
5. 打开详情；
6. 查看示例、输入和步骤；
7. 选择变量；
8. 点击复制；
9. 成功则显示已复制；失败则给出原因和手动复制方案。

### Journey B｜从搜索引擎直达详情

1. 用户打开静态 L4 URL；
2. 首次 HTML 已含 H1、摘要、Prompt、步骤、来源和相关链接；
3. 页面语言与 URL 一致；
4. 用户复制或进入同模型/同用途页面。

### Journey C｜编辑到发布

1. 审核者从候选建立 PromptArtifact；
2. 在 Payload 保存 en/zh-CN 草稿；
3. 校验字段、翻译、来源、媒体与 rights path；
4. reviewer/admin 对精确 content/source/rights revisions 执行人工批准；
5. CMS 生成不可变 export snapshot，并提供受 Access 保护的 noindex Preview；
6. exporter 在临时目录确定性生成 Markdown、rights registry、索引和多语言 README；
7. 校验全部通过后，专用 mirror bot 把完整 snapshot commit 直接 fast-forward push 到公开镜像 `main`；
8. post-push verify 通过后，以该 mirror commit 与 manifest 部署生产；
9. 页面、RSS/Sitemap 更新；
10. 部署成功与 smoke 证据匹配 mirror commit/hash 后，Payload 才显示 released；失败则显示 mirror_failed 或 deploy_failed，并继续服务 last-known-good。

### Journey D｜自然语言编辑到 CMS review-ready

1. 内容工程用户在 Codex/Claude Code 中，或通过受控 Codex SDK runner，提出“加一篇博客”“改标题”“挂到 `/blog`”等请求，并提供正文、outline 或明确 brief；
2. Agent 读取项目规则、CMS contract 与当前 revision，确认 immutable id、locale、来源和目标路由；
3. Agent 只生成目标内容与必要 taxonomy/surface/redirect 的 CMS draft proposal；新内容默认 draft/noindex、rights review required；
4. Agent 运行 schema、locale/slug、链接、媒体、secret 和 proposal-scope 校验；
5. 用户在 proposal diff/CMS Preview 中确认内容与范围；
6. Agent 生成 review-ready 摘要；人类 reviewer 在 CMS 完成批准，Agent 不得自行设置 approved 或 rights；
7. 已批准 revision 进入 Journey C 的统一 snapshot/export/mirror/deploy 链。Agent 不编辑生成的 `content/**`，也不获得 mirror bot 或 released 权限。

Journey C 与 Journey D 只是草稿入口不同；从 CMS revision-bound 人工批准开始必须收敛为同一 snapshot、镜像和线上结果。

## 6. 全局产品规则

### 6.1 筛选

- 同一轴多个值为 OR；
- 不同轴之间为 AND；
- q 与所有 axis 为 AND；
- filter、sort、window、cursor 进入 URL；
- 刷新、分享、前进后退后状态不丢；
- 未知参数显示可恢复错误，不静默忽略；
- count 只能来自真实索引/API。

### 6.2 时间与热榜

- 7d/30d 使用 observedAt/publishedAt 动态计算；
- UI 显示互动数据快照时间；
- high-like/high-value 是内部数据规则，不宣称 X Trending；
- 排名规则和 indexVersion 可追溯。

### 6.3 Copy

- 复制原始 Prompt 时保留换行；
- 变量以明确 token 替换，如 COUNTRY；
- 所有 token 必须被替换或给出未替换警告；
- clipboard 成功后才显示“已复制”；
- 权限拒绝时显示“复制失败，可选中文本手动复制”；
- 不在失败时发 copy_success 事件。

### 6.4 空、错与加载状态

所有异步区域必须有：

- skeleton；
- empty；
- error；
- retry；
- stale data 提示。

页面级必须有：

- 404；
- locale variant not found；
- content retired/tombstoned；
- media unavailable；
- Preview/Access denied；
- 通用错误。

### 6.5 无假入口

原型中的“设置、参考图、生成”如果没有真实能力，internal beta 必须隐藏或明确标记“即将推出”；不能展示无行为主按钮。

## 12. 多语言

### 12.1 Locale 与生成文件

- 同一内容共享 immutable id；
- CMS 中每个 locale 保存独立 variant/revision；exporter 为每个 approved locale 生成 `en.md`、`zh-CN.md` 等镜像文件；
- 每个 locale 有独立 slug、title、summary、body、SEO；
- 详情与实体 API 通过 localeVariants 返回目标 locale 的 slug 与 href，语言切换禁止用当前 slug 猜目标 URL；
- Prompt 原文不因页面 locale 自动变化。

### 12.2 状态

missing → draft → review → ready → stale

- ready 才能公开；
- 源 revision 变化后译文自动 stale；
- stale URL 可保留旧线上版本，但不发布新 revision，后台显示阻塞；
- beta 也可选择临时 noindex，不能自动 fallback。

### 12.3 hreflang

- 只输出相互可访问的 ready locale；
- 每个 alternate 必须双向；
- canonical 指向当前语言自身；
- x-default 只有明确默认落地页时输出；
- 缺译文不生成伪 alternate。

## 13. PSEO 与 SEO 规则

### 13.1 页面资格

每个 indexable 页面必须有：

- 不同用户任务；
- 可追溯 evidence；
- 最小任务完成信息；
- 独特标题、描述和正文价值；
- 真实关系和内部链接；
- ready locale；
- 合规审核。

关键词 token 不是自动页面；Graph 的每条边也不是自动页面。

### 13.2 页面元数据

所有公开页：

- 唯一 title；
- 唯一 meta description；
- canonical；
- robots；
- Open Graph/Twitter card；
- BreadcrumbList；
- 适合页面类型的 JSON-LD。

L1/L2/L3 可使用 CollectionPage + ItemList；L4 使用 CreativeWork 等与可见内容一致的类型；Blog 使用 Article。只有页面真实展示完整步骤时才使用 HowTo。禁止为了富结果虚构 schema。

### 13.3 Sitemap

- sitemap index 按 locale + type + shard 分片；
- 只含 canonical、published、indexable；
- lastmod 来自实质内容 commit，不是每次构建时间；
- 接近平台文件限制前预警；
- URL 删除使用 410/redirect 规则并从 sitemap 移除。

### 13.4 Preview

- CMS revision Preview 必须 noindex；
- robots 禁止抓取；
- Cloudflare Access 保护；
- 页面明显标记 CMS content/source/rights revision；已生成的 mirror smoke 另标 export revision、commit 和 manifest hash；
- Preview URL 不进入公开内链、RSS 或 sitemap。

## 16. 内容来源、证据与审核

### 16.1 Source → Artifact

~~~text
Source
→ raw payload
→ normalized candidate
→ Prompt extraction
→ taxonomy
→ evidence/review
→ PromptArtifact
→ locale variants
→ CMS human approval
→ immutable export snapshot
→ generated Git mirror
~~~

原帖不是自动页面。系统必须让审核者判断：

- 是否真的包含可复用 Prompt；
- Prompt 是否完整；
- 适用模型/用途/技法/风格；
- 示例是否证明效果；
- 是否存在名人肖像、成人、未成年人、冒充或版权风险；
- 是否满足页面资格。

### 16.2 Rights 路径

| 来源 | Rights Status | 处理 |
| --- | --- | --- |
| 作者投稿并确认授权 | `cleared` | 保存授权、reviewer、时间和许可证证据，可进入 approved snapshot |
| 原页面明确标注兼容许可证 | `cleared` | 保存原页面、许可证 URL/版本和署名要求，可进入 approved snapshot |
| 仅从 X/公开社区采集 | `community_attributed` | 作者保留权利；公开时必须显示作者、原帖、删除入口和 no-CC notice |
| 未完成审核 | `review_required` | 只留在 CMS/Access Preview，不导出公开镜像 |
| 投诉或限制内容 | `restricted/takedown` | 阻止导出并事件触发 removal mirror/deploy |

`community_attributed` 是人工接受的 notice-and-takedown 路径，不是版权许可。现有 35 条 seed 不因采用本策略自动转换或公开；必须先完成逐条 readiness report 和 owner 明确批准。完整字段、状态迁移、许可证范围与门禁以 0011 §4 为准。
