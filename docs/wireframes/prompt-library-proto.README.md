# 提示词库 L1–L4 交互原型（4 个方向）

`prompt-library-proto.html` —— 单文件，双击即可在浏览器打开，无需服务器、无外部依赖。

底部深色药丸是**原型选择器**（harness chrome，不是设计的一部分）。
`1`–`4` / `←` `→` 切换方向，`R` 重新播放进场动效，选择写入 `?v=`，刷新保留。

站内导航是真的：点卡片进详情、点面包屑返回、点模型进模型页。四个层级都在同一个文件里。

| 键 | 作用 |
| --- | --- |
| `1`–`4`、`←` `→` | 切换设计方向 |
| `R` | 重放进场动效 |
| `/` | 聚焦搜索框 |
| `Esc` | 清空搜索 / 清除筛选 |
| `↑` `↓`（或 `j` `k`）| Console 方向：移动选中行 |
| `C` | Console 方向：复制选中行的提示词 |
| `↵` | Console 方向：打开详情 |

## 四个方向

每个方向都是**一套完整的 L1–L4**，共用同一套 token、同一份数据、同一个筛选/复制/路由引擎。
分歧只发生在布局、密度、交互模型和动效上——不在颜色和字体上。

### 1. Gallery — 结果优先

**轴：视觉扫描。** 出图结果是浏览的最小单位，提示词正文退到一次交互之后。
统一 4:5 网格、行优先排序、hover 浮出标题与复制按钮；纯文字提示词占同样大小的格子，
用等宽正文加底部渐隐当作它自己的「封面」。

- **什么时候它对**：用户"想要那种感觉的图"但说不出关键词。对图像/视频提示词库这是最自然的入口。
- **代价**：正文（也就是 Google 真正要读的东西）在视觉上被压到最次要；纯文字提示词天然吃亏；媒体加载最重。

### 2. Console — 密度与键盘

**轴：熟练用户的速度。** 左筛选栏 / 中结果列表 / 右实时预览。
比较两条提示词只要一次按键，不需要两次页面跳转。行高 44px、tabular 数字、`aria-activedescendant`。

- **什么时候它对**：每天用几十次的人。挑选、比对、复制，全程手不离键盘。
- **代价**：它读起来像一个应用，不像一个内容站——从 Google 落到 L2/L3 的冷启动用户会有点懵；
  窄屏下右预览栏必须整个收掉（已处理：窄屏点行直接进详情页，不会点了没反应）。

### 3. Editorial — 文档化、SEO 原生

**轴：可读性与可抓取性。** 单栏、624px 正文宽、真实的 `h1/h2/h3` 层级、
每条提示词是一个编号条目（编号 + 标题 + 署名 + 配图 + 正文块 + 标签），页内还有目录。
每个 facet 都是真链接，分页是真 `<a href>`。

- **什么时候它对**：这是 Google 实际会排的那种页面形状。也是手机上最好读的一版。
- **代价**：密度最低，滚动最长；对"我只是想看看有什么图"的用户最不友好。

### 4. Workbench — 提示词是模板，不是句子

**轴：交互模型本身不同。** 抓住原 L4 里 `[COUNTRY]` 的那个洞察并把它推到全站：
提示词被解析成带**槽位**的模板，浏览＝挑模板，使用＝填槽位。
列表卡片上直接点变量就能换值，复制出来的是**替换后**的版本；详情页是一个工作台——
左边表单，右边正文实时替换并高亮，字符数实时更新。

- **什么时候它对**：这是四版里唯一一个别家提示词库没有的东西。换一个国家，地标、服饰、货币、
  邮戳整套联动更换——一条提示词就是一个系列，这个价值现在是**看得见**的。
- **代价**：只有带占位变量的提示词吃得到这套交互（当前样本 35 条里只有 4 条）。
  其余的会退化成一张普通卡片，需要有一个说得过去的"整段即用"叙事（已做）。

## 关于 footer

按要求保留，并且四个方向里**都在**：6 列 × 40 条真实 `<a href>` 内链
（模型 / 任务 / 镜头技法 / 风格 / 创作者 / 资源），每条带真实数量。
这是 pSEO 站的内链面，不是装饰，所以它没有被任何一版牺牲掉。

## 数据

不是假数据。全部从 `flow-proto-full.html` 里抽出来的真实记录：
**35 条提示词**（33 条带真实媒体）、真实作者 handle、真实原帖链接、真实赞/藏数、
真实 taxonomy 计数（Seedance 272、Cinematic 416 等来自原 wireframe）。

原型只载入 35 / 982 条，这一点在页脚和空态里都**明确写出来**了，没有拿占位数据冒充。
交互筛选的计数反映的是这 35 条样本；taxonomy 内链上的计数是全站真实数字。两者在文案里是分开的。

## 一处刻意的改造

原 wireframe 里的卡片标题是 `{ "image_analysis": { "overall_scene": "Provocative gym…`——
对人和对 Google 都是废的。原型加了一个**确定性的标题推导**：
JSON 正文按 `full_text_prompt` → `prompt` → `overall_scene` … 的优先级取出真正的提示词字段，
在词边界截断。**不翻译、不改写、不编造**；提示词正文本身逐字未动
（`text-transform:none`、连字与 ligature 关闭、`lang="en"`、等宽栈带 CJK 回退）。

## 已验证

在 `http://localhost` 真实 origin 下逐项跑过（不是看截图猜的）：

- 4 方向 × 4 页面 = 16 种组合全部渲染，**零 console 报错**，每页恰好一个 `h1`，无标题层级跳级
- 375px 宽下 16 种组合**均无横向溢出**
- 筛选 / 搜索（含防抖与焦点保持）/ 排序 / 分页 / 清除，状态全部写进 URL，可分享、可后退
- 复制：主路径 + `execCommand` 回退 + 失败态（按钮改文案、toast 提示、1.6s 后复原）
- Workbench：卡片槽位循环 → 状态带进详情页 → 预设 → 自由输入 → 系列切换 → 恢复原文，全链路通
- Console：`↑↓ / j k / C / ↵` 全部生效；窄屏预览栏隐藏时点行会进详情而不是无反应
- 无 `transition: all`；只动 `opacity/transform/box-shadow/color/background-color/border-color`；
  从不动 `outline-*`；4 处 `prefers-reduced-motion`；22 处 hover 门控在 `hover:hover` 内
- 命中区：桌面 ≥40px、`pointer:coarse` 下 ≥44px；扩展量都小于容器 gap，互不重叠
- 深色 / 浅色两套配色都过（`light-dark()` + `color-scheme`，跟随系统，无主题开关）

## 设计依据

颜色、字重、圆角、阴影、动效时长与曲线全部取自 `frontend/AGENTS.md` §7（Linear 派生体系），
包括：只用 400/600 两档字重、不加载 web font、每屏只允许一个靛蓝填充主动作、
表单控件轮廓自身达 ≥3:1、hover 只改投影不移动对象、UI 动效一律 < 300ms、禁用 `ease-in`。
