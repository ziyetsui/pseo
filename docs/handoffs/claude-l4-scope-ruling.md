# L4 详情页模块裁定

Status: 裁定（对实现生效）／对 `specs/0008-prd.md` §10.2 为替代提案，待规范负责人采纳
Date: 2026-09-03
Scope: `/{locale}/prompts/{promptSlug}`，即 PRD §10 的十四项「必需模块」
依据：对 fixture 全部 35 条记录的实测，不是偏好

## 0. 一句话

十四项里有七项在 35 条记录中只有 1 条有数据；把它们渲染出来会在 34 个页面上留下空标题。
**维持删除**，并把其中三项从「本期不做」改判为「永久删除」——因为它们即使有数据也是重复。

## 1. 覆盖率实测

| 模块 | 有内容的记录 | 判定 |
| --- | --- | --- |
| 媒体 | 34/35 | 保留 |
| 点赞 / 收藏 | 35/35 | 见 §3 |
| 浏览 / 转发 / 评论 / 引用 | 1/35 | 删除 |
| 摘要 summary | 1/35 | 见 §4 |
| 变量 | 1/35 | 条件渲染（已是） |
| 使用步骤 | 1/35 | 永久删除 |
| 必需输入 | 1/35 | 条件渲染（已是） |
| 可选输入 | 0/35 | 删除 |
| 参数 | 1/35 | 永久删除 |
| 同系列 variations | 1/35 | 永久删除 |

## 2. 逐项裁定

### 永久删除（即使补齐数据也不恢复）

**参数。** 唯一一条有参数的记录，四个值全部是提示词正文的**逐字子串**，而正文就印在它上方同一屏：

| 标签 | 值 | 是否正文子串 |
| --- | --- | --- |
| 分辨率 | `8k resolution` | 是 |
| 渲染器 | `octane render` | 是 |
| 镜头 | `tilt-shift lens effect` | 是 |
| 景深 | `shallow depth of field` | 是 |

这不是摘要，是同一段文字换个版式再印一次。

**使用步骤。** 三条理由，任何一条都足够：
1. 1/35 覆盖率。
2. fixture 里步骤 3 的正文是「7 处全部替换为同一国家名」——正文中 `[COUNTRY]` 确实出现 7 次，但 PRD §10.4 明令「替换次数由 parser 决定，不硬编码『7 处』」。这个模块的内容本身就违反它所属规范的验收条款。
3. 步骤 1「打开 bo，在模型列表中选择 GPT Image 2」在每一页都会是完全相同的样板文字。程序化 SEO 最怕的就是逐页复制的正文。

**同系列 variations。** 六条全部 `status: "pending"`、`media: null`。这是六个占位框，不是内容。

**Outcome（能得到什么）。** 唯一一条有 summary 的记录，`summary` 与 `excerpt` **逐字相同**。Outcome 会成为同一句话在同一页上的第三次出现。而且 outcome 本来就由媒体直接呈现——图就在那里。

### 保持不渲染，但记为「等字段」，不是「已裁掉」

**Evidence。** `PromptDetail` 上根本没有 evidence 字段，没有内容可渲染。
PRD §10.3 要求「source、evidence、example 不得合并成一个模糊『来源』字段」——当前来源区块与媒体区块是分开的，没有违反该条。字段落地后重新评估。

### 形式改判

**相关：三栏 → 单栏。** 模块保留。三栏形式删除：`sameSeries` 在抽样的 6 条里有 3 条为 0，三栏排布会稳定地出现空栏。按有内容的分组顺序单栏排列。

## 3. 互动数据：一个数，不是六个

批准当前实现（点赞 + `observedAt`，仅 L4）。

原六格网格里，浏览／转发／评论／引用四项覆盖率都是 1/35——网格在 34 个页面上是四个空格加两个数。

**收藏数不加回来**，尽管它覆盖率同样是 35/35，且抓取规范把 `bookmarks >= 100` 当作高复用价值信号。理由是页面任务：PRD §10.1 说 L4 的任务是「让用户以最少不确定性复现一个结果」。指标服务的是**挑选**，那是 L1–L3 的活。L4 只需要一个数回答「这条值不值得用」，两个数并排只会让读者做一次没有结论的比较。收藏率留在排序信号里，不进页面。

## 4. 真正的问题不在模块，在内容

裁定过程中量到一件比模块取舍严重得多的事：

**35 条记录里，34 条的标题和正文没有任何一个汉字。**

- 标题含汉字：1/35。其余 34 条的 H1 是被截断的英文提示词片段，其中一条是原始 JSON：`{ "scene_type": "indoor close-up lifestyle selfie", "setting": {`
- `summary` 为 null：34/35；这 34 条的 `excerpt` 同样零汉字，因为它是提示词正文的又一次截断。

后果：这 34 个页面挂在 `/zh-CN/` 路由下，但页面上没有中文可供中文查询命中；H1 是正文的子串；`generateMetadata` 回退到 `excerpt`，于是 meta description 也是同一段英文。

**这不是前端缺陷，前端渲染的是它拿到的东西。** PRD §10.2 要求 Identity 有 title 与 summary，Tech Arch §Identity 要求「slug、title、description 在 locale 内唯一」，但没有任何一条说明它们从哪里来。fixture 只有那一条黄金记录是人工写过的。

**给规范负责人的问题：zh-CN 的 title 与 summary 由谁产出？** 人工撰写、LLM 生成后人工审核，还是别的？在有答案之前，往 L4 上加模块不会改善任何排名——空模块只会提高样板文字占比，让 34 个本已高度雷同的页面更雷同。

有一处因此悬空：`generateMetadata` 用 `summary ?? excerpt`，所以 meta description 有文字而页面正文没有。把 excerpt 印到正文里不是解法——那是把同一段英文在一页上印两遍。保持现状并记录，等 title/summary 的来源确定。

## 5. 与 pseo-75 的关系

pseo-75 要求把它的删减记为**意见**而非决定，这是对的。本文件把其中可实测的部分转为**裁定**，依据是覆盖率与重复性实测，不是同意或不同意某个会话。工作树中 `PromptDetailView.tsx` 的未提交实现与本裁定一致，予以批准。
