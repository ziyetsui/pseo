# 按变现场景浏览：验收规范

状态：待评审；没有执行实现或发布验收。依据：[技术设计](./2026-10-16-monetization-views-design.md)。

## 1. 基线与交付证据

冻结实施时 beta 的真实 revision、代码提交、源文件哈希、两语言全部 ID 和已存在详情路由。检查时观测为 2,034 条提示词、225 个网站入口；它们存在重叠，禁止直接相加。内容变化时更新基线并重跑映射验证，不把旧数量作为新站正确性的证明。

输出可复查回执：`baseline.json`、`classification-audit.json`、`route-audit.json`、`browser-results.json`、桌面/手机截图和部署回执。回执记录真实命令、状态和时间，未执行项目标为未执行；不写入秘密、Cookie 或账户信息。

## 2. 数据验收

| 检查 | 通过标准 |
| --- | --- |
| 候选定义 | 恰好 8 个大类、40 个初始场景；ID/slug 唯一率 100%；每个场景恰有 1 个合法父大类 |
| 双语 | 大类/场景名称、说明、规则及需要展示的改编说明在 en/zh-CN 完整率 100%；两语言成员 contentKey 集合一致 |
| 全量检查 | 每个基线逻辑内容恰有 1 个审计结论，覆盖率 100%；已映射、无相关、待审核之和等于唯一内容总数 |
| 真实成员 | 0 个悬空内容 ID、场景 ID、父节点或源 revision；每条关系有可定位正向证据，完整率 100% |
| 可解释分类 | direct/adaptable 为合法枚举；adaptable 双语改编说明非空率 100%；无理由的成员边为 0 |
| 去重 | `contentKey + scenarioId` 重复为 0；网站/所附 Prompt 别名按同一规则归一；场景、大类、总数及筛选后数量均精确等于集合并集 |
| 空分类 | 有效场景至少 1 条核验成员；0 成员候选不出现在展示导航、路由 manifest 或目录索引；有待审核成员不等于有效成员 |
| 内容不变 | 原正文、来源、原作者、语言、reconstruction、已有 ID/详情 URL/权利状态对基线差异为 0；新映射不复制正文 |
| 收益事实 | 未经证据支持的收入、成交、转化率、平台认可、作者已变现等断言为 0 |

不要把“成功映射比例高”本身当作质量目标。未知/无关记录允许不映射，但必须可解释。

分类质量检查：对每个非空场景复审最多 5 条成员，优先同时覆盖 direct、adaptable 和不同媒体/来源；成员不足 5 条则全部复审。初始 40 场景最多复审 200 条场景关系，另检查全部归一别名冲突与全部异常。任一误归类须修正并重审该场景；正式回执列出复审 ID、证据及结论。

必须包含的反例：普通人物写真不自动归女装带货；泛漫画不自动归情感漫画；小红书界面截图不自动归带货；全部文章封面不自动当公众号原生模板；仅含商店背景的照片不当电商网站；negative prompt、否定表达、参考 URL 中的命中不产生关系。

## 3. 四层路由与导航

- 两语言的维度目录、所有有效 L2/L3 页面、其 L4 引用均进入静态路由校验；内部链接 404/空 href/假 hash 入口为 0。
- 新增逻辑页面数必须等于 `2 × (1 + 有效大类数 + 有效场景数)`，最多 98；不新增 L4 内容副本。
- 所有有效 L2/L3 直达、刷新、前进后退均可用；未知 slug 与错误父子组合返回真实 404。
- 首页有效大类卡片最多 8 张，展示计数与详情集合一致；卡片进入 L2，L2 场景卡进入 L3，L3 标题/卡片进入已有 L4。
- 原有任务、模型、风格、网站视图及详情路由集合丢失数为 0。
- L4 相关场景入口均来自同一成员关系，不静态猜测 slug；无提示词项目的生成按钮数为 0，来源/演示/代码仍可用。

## 4. 首页、页脚与目录

页脚全页面一致为五列，按变现列最多 6 项（最多 5 个非空精选场景 + 完整目录）。前四列保留基线内容和相对顺序。第五列的每条链接存在且目标非空；目录中有效大类和场景覆盖率 100%，同一组重复 href 为 0。

在 1,440×900、768×1,024、375×900、320×900 检查：1,440px 五列；手机两列并允许末列独占一行；页面 `scrollWidth <= innerWidth + 1`。横向卡片区的内部滚动合法，但不能使整页溢出。标题和计数无不可读裁切，触摸、箭头和键盘均能访问所有卡片。

## 5. 交互与语言

浏览器覆盖两语言、桌面和手机：至少 1 条 direct 场景旅程、1 条 adaptable 场景旅程、1 条网站案例旅程。固定夹具提供所有状态的确定性验证；真实数据若缺某状态必须如实报告，不造线上案例补测试。

每条旅程执行 L1→L2→L3→L4→返回；L3 的类型/模型筛选写入 URL，刷新和返回恢复选择，清空恢复原场景集合。语言切换停留同场景并保留合法 query/hash。已选条件不得因选项显示上限而消失。

中文界面新增未翻译英文文案为 0，英文界面新增未翻译中文文案为 0；来源正文、专有名称与印在图片中的文字不作错误翻译。direct/adaptable 标签与改编说明必须清晰可区分。

生成按钮解码后的 `prompts` 参数与当前完整正文逐字符相等：覆盖中文、英文、换行、特殊字符、JSON、变量填写与重置。模型草稿、提醒弹窗继续按钮沿用已有合同；标题/卡片仍浏览详情。无需真实执行付费生成。

## 6. 无障碍与无脚本

每页 1 个 H1；导航、滚动按钮、筛选与变量字段有对应语言可访问名称；键盘无陷阱、焦点可见。代表性 L2/L3、页脚与对话框执行现有 Axe 检查，新增严重及 critical 违规为 0。

禁用 JavaScript 后至少验证两语言 L1→L2→L3→L4 的真实链接，分类说明、计数、案例正文和来源可读。筛选增强可不可用，但不得仅靠客户端生成主体或通过 iframe 模拟页面。

## 7. 构建、性能与收录

- 在锁定依赖下运行适用的类型检查、lint、单元/合同测试、浏览器测试、完整 Git-beta 构建及静态输出检查。所有必需检查失败为 0；原有 lint 警告与新增问题分开记录。pnpm 命令带 `pnpm_config_verify_deps_before_run=false`，不刷新共享依赖。
- 构建不要求运行 CMS/后端，不依赖新外部内容 API。客户端映射与页面序列化不得包含全部目录正文；沿用现有媒体懒加载，单次 Deck 首屏只加载当前与 3 个预览卡片媒体。
- 测量同一机器、相同配置下构建时间、发布文件数、总字节、代表 L2/L3 HTML 与客户端载荷字节；逐项报告与基线差异，不把缓存差异解释为性能优化。
- 最终 Pages 文件数不超过 20,000；所有已保留的路由代理、RSC/脚本/字体/媒体引用校验通过。不能删除旧案例或私自删内容满足容量。
- beta 新页面 noindex 覆盖率 100%，进入可索引 sitemap 的新增页为 0；语言路由和 canonical 不跨大类/场景混淆。正式搜索收录不在本次发布验收中。

## 8. 发布通过条件与回滚

实施前完成代码/数据基线对齐并复核。提交工程 PR，记录检查状态；合并状态、beta 构建状态、Pages 发布状态、真实 beta 别名线上 smoke 状态分别报告。目标仓库同步或静态包完成均不等同 beta 上线。

线上 smoke 至少检查：中英文首页新入口、维度目录、2 个不同大类、2 个不同场景、原有图片/视频/网站入口、原有 L4、页脚第五列及语言切换；HTTP 成功、无缺失脚本/字体及无新增 hydration 错误。保存实际部署 revision 和响应证据。

应用端超长提示词 431 单列为已知依赖。网站链接可按合同通过，不能据此声称应用端完整接收通过；接收端修复需另外验证完整正文经登录前后预填。

发布失败恢复上一包；分类错误移除/修正关系并重新计算全部计数与页面，再重新验证。回滚后原有详情 URL 和源内容完整性仍需通过基线比较。
