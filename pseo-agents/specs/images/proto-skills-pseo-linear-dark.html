A skill for every step of programmatic SEO

Install them into your coding agents with a single command:

npx skills add ziyetsui/pseo --skill pseo

Run it in your terminal, choose whether to install into the current project or globally, and pick the skills you want. The entry point /pseo reads docs/pseo/project.json, works out which stage you're in, and calls the next skill. You can also grab one directly, like npx skills add ziyetsui/pseo --skill pseo-site-audit.

Available skills 25

Grouped by the six phases of the main /pseo table, in the order a real project runs them. Click any skill to see what it does, what it needs, and what it delivers.

Entry points

Start with /pseo when a site already exists; it reads the project record and picks the next step. Start with the wireframe when there is only an idea.

/pseo Use it first: it reads docs/pseo/project.json, tells you which stage you're in, and picks the next skill. /pseo-wireframe Use it when you only have an idea and want to walk, option by option, to a browsable wireframe of the whole site.

01 · Direction

Understand the site as it is, choose the first page family, and cluster what users are actually asking for.

/pseo-site-audit Use it when you already have a website and want to know where PSEO should start. /pseo-opportunity Use it when you have a few directions and need to pick the one page family worth validating first. /pseo-intents Use it when you have keywords or customer questions and need to know which ones one page should answer.

02 · Data

Decide where the facts come from, bring them in with boundaries, and model entities and relations before any page exists. The graph now exports the neighborhood view every page footer is built from.

/pseo-sources Use it when the direction is chosen but you don't know what data will keep the pages alive. /pseo-ingest Use it when API, CSV, or web material has to become data you can check and re-run. /pseo-graph Use it when you have a pile of material and need entities, attributes, and relations pages can reuse.

03 · Pages

Decide which pages deserve to exist, specify what each must show, prototype it with real records, then make it look designed. The IA footer is a required module.

/pseo-page-plan Use it when data and user tasks exist and you need to decide which pages, navigation, and internal links deserve to exist. /pseo-page-spec Use it when you know which pages to build and must define what each one has to show. /pseo-prototype Use it when you want to see the page before development and check that it really completes the user's task. /pseo-prototype-polish Use it when the prototype works but looks assembled, and you want it to look designed, or to compare a few directions.

04 · Integration

Plug into the stack the site already runs on, implement the first family, and verify the real HTML.

/pseo-architecture Use it when the prototype is settled and you have to decide how data, templates, and publishing plug into the existing site. /pseo-implement Use it when the spec is clear and you're wiring data and templates into real code. /pseo-technical-seo Use it when the pages work but you need proof they're crawlable, URL-consistent, and free of index conflicts.

05 · Release

Define who drafts and who reviews, gate every page, and ship only with authorization and receipts.

/pseo-content-workflow Use it when content will keep coming and you need to say who edits, who reviews, and where it publishes from. /pseo-quality-gate Use it when you have candidate pages and want to know which can go to release review and which must be stopped. /pseo-release Use it when the first batch has been reviewed and needs a safe, authorized release with real receipts.

06 · Learning

Get a baseline, fix what is already live, and only then decide the next batch.

/pseo-measure Use it when pages are live, or before that, to define how you'll judge whether they work. /pseo-refresh Use it when pages are stale, slipping, or overlapping and you want to fix them before adding more. /pseo-expand Use it when the first page family is proven and you're deciding what the next batch should be.
